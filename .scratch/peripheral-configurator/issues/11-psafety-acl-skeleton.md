# TICKET-11: `psafety` — ACL, `SafeCommandId`, rate limiter, journal (skeleton)

## Status

DONE_WITH_DEVIATIONS (2026-08-18) — все acceptance criteria выполнены; пять отклонений, все additive или архитектурно более строгие, см. Deviations.

Порядок закреплён 2026-08-17: после TICKET-08 проект впервые приблизился к настоящему I/O, поэтому архитектурная гарантия `raw opcode ✗ → SafeCommandId ✓ → Safety Gate ✓ → Transport` фиксируется **до** появления первого protocol engine. Ни один engine не должен получить возможность случайно обойти safety boundary.

## Objective

Реализовать `psafety`: классификацию опкодов (`safe_read`/`safe_write`/`probe_ok`/`slow_flash`/`destructive`/`unknown`, дефолт `unknown` = запрещено), build-time codegen `SafeCommandId` (closed enum из записей реестра с классом ≠ `destructive`/`unknown`), rate-limiter skeleton (per-family/per-opcode-class), journal skeleton. **До любой записи в устройство** — этот тикет обязан существовать раньше TICKET-12's write-путей (у TICKET-12 в этом тикет-сете есть только read, поэтому формально не блокирует, но по духу спецификации (FR2/FR3) должен быть готов прежде, чем какой-либо будущий write-тикет начнётся).

## User or system value

Это архитектурная гарантия безопасности продукта (spec FR2/FR3, plan §10.6) — единственное, что стоит между кодом и окирпичиванием чужой платы. Не опция, а инвариант.

## Dependencies

TICKET-07; координируется с TICKET-10 по формату `opcode_acl`-таблицы (обе используют одну и ту же схему реестра из `spec.md` Приложение B).

## Scope

- `opcode_acl(protocol_family, opcode, class, note)` — источник для codegen.
- Build-script/codegen: `SafeCommandId` enum, содержащий **только** варианты для opcode с классом `safe_read`/`safe_write`/`probe_ok`/`slow_flash`; `destructive`/`unknown` физически не попадают в enum.
- Compile-time seam test (см. `spec.md` Test seams): тестовый реестр с намеренно "плохой" записью (`destructive`-опкод) — codegen обязан не породить для него `SafeCommandId`-вариант.
- Rate limiter: интерфейс, принимающий family + opcode-class, состояние "endpoint жив/stalled" — для Phase 1 read-only сценария реализация может быть минимальной (нет write-нагрузки ещё), но контракт должен быть готов под будущий `light.per_key`/flash-write сценарий (Phase 2+). Rate limiter не владеет физическим handle и не делает I/O напрямую — он выдаёт разрешение/отказ команде, которая затем идёт через `DeviceSession`'s command queue (TICKET-07/08 contract); "endpoint stalled" — это состояние, о котором `psafety` узнаёт от `ptransport`/сессии, а не то, что оно детектирует само через прямой опрос handle.
- Journal skeleton: запись каждого исполненного `SafeCommandId` (даже read) с таймстампом — основа для будущего Journal-экрана UI (TICKET-13).

## Out of scope

- Реальный backup/restore перед первой записью — Phase 2 (записи ещё нет в этом тикет-сете).
- Kill-switch на `Protocol error` — реализуется вместе с первым write-путём, Phase 2.

## Acceptance criteria

- [x] `SafeCommandId` enum генерируется на этапе сборки из `opcode_acl` реального реестра (`data/protocols/*.toml` → `build.rs` → `OUT_DIR/safe_command_id.rs`). Сгенерировано 16 команд по двум семействам; AULA — ноль.
- [x] Compile-time seam проходит: `destructive`-запись не производит `SafeCommandId`-вариант. Проверено двумя способами — юнит-тестами генератора над синтетическим «плохим» реестром и интеграционным тестом `tests/forbidden_commands.rs` над реальными данными. Дополнительно проверено, что опкод не попадает даже в *текст* сгенерированного файла. `trybuild` не использован — см. Deviations.
- [x] Исполнитель принимает только `SafeCommandId`; ни одна публичная функция крейта не принимает опкод. `SafeCommandId::opcode()` — `pub(crate)`, байт читается ровно в одном месте.
- [x] Journal фиксирует каждый вызов, включая read и **включая отказы**, без содержимого payload.

## Implementation notes

### Что стоит между кодом и чужой платой

```text
engine
  │  сырой опкод            ← такого типа нет и такой функции нет
  ✗
  │  SafeCommandId          ← генерируется из размеченных данных;
  ▼                            destructive/unknown не имеют варианта
SafetyGate::execute
  │  устройство опознано? то ли семейство? есть backup?
  │  вписывается в измеренную каденцию? не в карантине?
  ▼
AuthorizedCommand          ← приватный конструктор, не Clone,
  │                           потребляется при dispatch
  ▼
CommandSink → DeviceSession → провод
```

Ключевое устройство границы: **гейт владеет sink'ом, а не одалживает его**. Engine держит `&mut SafetyGate` и не имеет объекта, через который можно отправить что-то мимо. `AuthorizedCommand` невозможно ни сконструировать снаружи, ни переиграть — он потребляется по значению.

### ACL

`data/protocols/*.toml`, по файлу на семейство, схема `peripheral.opcode-acl/1`. TOML вместо YAML: файл читает build script, парсер — часть границы безопасности, поэтому взят поддерживаемый парсер с `deny_unknown_fields` (опечатка в имени поля обязана ронять сборку, а не игнорироваться). Записано в `data/protocols/README.md`.

Build script падает, а не предупреждает, на: отсутствующем/незнакомом классе, незнакомом поле, дубле опкода или имени внутри семейства, отсутствующем note, write-классе на evidence слабее собственного железа, read-классе на vendor-JS, классе без измеренного тайминга, `slow_flash` с нулевым settle,半 burst-лимите, неизвестной схеме. Проверено end-to-end: попытка внести `0xAC` как `safe_write` роняет `cargo build` с сообщением, называющим файл, опкод и что делать вместо этого.

### Что реально сгенерировалось

16 команд: 8 на `royuan-gen2`, 8 на `royuan-yc500`, **все — `safe_read`/`probe_ok`**. Ноль write-команд во всём реестре. У `aula-hero84-he` — ноль команд вообще: семейство объявлено, опкодов нет, потому что после TICKET-08 о содержимом vendor-каналов не известно ничего. Отсюда механическая гарантия: этот тикет физически не мог записать что-либо в нашу плату.

ROYUAN-данные взяты из `docs/prior-art/royuan.md` (факты, не код — ADR-0001) ради того, чтобы кодоген проверялся против настоящих размеченных данных, включая настоящие деструктивные опкоды. Ни движка, ни платы этого семейства нет; присутствие в ACL ничего не разрешает.

### Rate limiter

Два числа на класс, а не одно: `min_gap_before_ms` и `settle_after_ms` — тишина после совершённой операции. Settle применяется ко **всему** последующему трафику устройства, включая чтения: тест `the_quiet_after_a_flash_write_applies_to_everything_that_follows` фиксирует именно это. Плюс burst-окно (`2 загрузки / 10 с` у ROYUAN). Все числа — из ACL-файла семейства, с указанием, где измерены; глобальных констант в коде нет.

Неизвестное семейство (или известное, но без измерения для этого класса) → `NeedsConfirmation`. Никаких «безопасных 12 мс» по умолчанию. `UserConfirmation` принимается **по значению**, поэтому согласие на одну операцию не может стать согласием на серию; batch-входа в гейт нет вовсе.

### Kill switch

Только типизированный `TransportError::EndpointStalled` переводит устройство в карантин. Карантин запрещает и чтения тоже, снимается исключительно `device_reconnected()`. Ретраев нет нигде на пути. Текст ошибки backend'а не разбирается — прямое следствие находки TICKET-08.

### Journal

Событие на каждую попытку: время, устройство, семейство, имя команды, класс, intent, **длина** payload, outcome (`Completed`/`Refused(причина)`/`Failed(тип)`), verification. Байтов payload нет ни в каком виде; ошибка транспорта записывается типом, а не сообщением. `JournalSink` реализует вызывающий — крейт не тянется вверх по DAG к `pjournal`.

### TDD

Тесты писались до реализации для генератора и rate limiter'а; у limiter'а был настоящий red→green (границы burst-окна: запись в момент `t=0` выпадала из окна, тест поймал). Тесты гейта писались вместе с реализацией, поэтому «красной» фазы у них не было — вместо этого их зубастость проверена мутацией: снятие family-check роняет 1 тест, снятие карантина — 3. Итог: 64 теста (56 unit + 8 интеграционных).

## Deviations

1. **`trybuild` не использован.** Тикет допускал «`trybuild`/аналог». `trybuild` сверяет вывод компилятора со снапшотом `.stderr`, а `rust-toolchain.toml` пинит канал `stable`, а не версию, — снапшот протухнет на первом же апдейте компилятора и уронит CI по причине, не имеющей отношения к безопасности. Для набора тестов, чья ценность в доверии, это плохой размен. Взамен: свойство обеспечено конструкцией (варианта не существует), а данные, от которых оно зависит, закреплены интеграционными тестами. Если появится job с пиннутой версией тулчейна — `trybuild` можно добавить туда.
2. **ACL в TOML, а не YAML.** `data/README.md` описывал YAML для всего каталога. Обоснование — выше и в `data/protocols/README.md`: единственный поддерживаемый YAML-парсер в экосистеме Rust помечен как deprecated, а парсер здесь — часть границы безопасности.
3. **ROYUAN-семейства внесены в реестр**, хотя ни платы, ни движка нет. Это осознанно: без реальных данных кодоген и его отказы проверялись бы только на синтетике, а деструктивные опкоды ROYUAN — самый честный доступный тест «эти байты не должны выжить». Ни одной write-команды при этом не сгенерировано.
4. **Гейт оперирует `DeviceId`, а не `SessionHandle`.** `SessionHandle` невозможно сконструировать вне `ptransport` (и это правильно), а трогать транспорт в этом тикете запрещено. Заодно вышло архитектурно чище: сессиями владеет sink, а не гейт, — второго места владения устройством не появилось (FR10).
5. **Backup заложен как факт, а не как содержимое.** `record_backup(device)` / `BackupState`; write-класс без записанного backup отклоняется. Что *внутри* backup и как его восстанавливать — не выдумывалось: первый read-only движок этого не умеет, это TICKET-15.

## Review findings

Самопроверка (полноценный `/code-review` в этой сессии заменён ей, как и в предыдущих тикетах).

Блокирующих findings нет. Два незакрывающих замечания:

1. **Последний участок пути держится на соглашении, а не на типах.** `ptransport` пока не имеет write-API; когда он появится (TICKET-12/15), он обязан принимать только то, что произвёл гейт. Сегодня sink получает `AuthorizedCommand`, но сам sink, будучи реализован поверх `DeviceSession`, технически может писать в устройство и мимо. Это прямо записано в doc-комментарии крейта, чтобы не выглядело закрытым.
2. **`build.rs` кладёт `data/protocols` на граф сборки**, то есть сборка крейта зависит от layout'а репозитория выше него. Известная цена, зафиксирована в `build.rs`: если станет мешать, ответ — xtask с закоммиченным сгенерированным файлом и проверкой в CI, а не рукописный enum.
