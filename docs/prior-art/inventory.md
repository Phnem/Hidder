# Инвентаризация prior art

Тикет: TICKET-03. Дата проверки лицензий: **2026-08-17**.
Правовая рамка: [ADR-0001](../decisions/0001-license.md) — приложение проприетарное, в шипящемся бинаре допустимы только permissive-зависимости (MIT/Apache-2.0/BSD/ISC); GPL/AGPL/LGPL-проекты используются **только как источник фактов или дизайн-референса**, без переноса кода.

## Легенда «режима использования»

| Режим | Что разрешено | Почему |
|---|---|---|
| `code` | брать/портировать код в продукт, сохраняя копирайт-нотис | permissive-лицензия (см. ADR-0001) |
| `facts` | извлекать протокольные **факты** (опкоды, длины пакетов, смещения полей, алгоритмы контрольных сумм) и переформулировать своими словами; код не копируется и не портируется | лицензия copyleft — факты об интерфейсе устройства не являются объектом её действия, конкретная реализация является |
| `docs` | использовать как дизайн/UX/терминологический референс | то же + польза проекта в основном не в коде |

Правило по умолчанию для лицензии, которую не удалось подтвердить: **`facts`, никогда не `code`** (тот же принцип «unknown = запрещено», что у `opcode_acl` в `psafety`).

## UX и архитектурные референсы интерфейса (TICKET-13)

Четыре проекта читались отдельно как источник **UX-решений и архитектурных
границ** для окна конфигуратора: Pipette Desktop, OpenRGB, libratbag/Piper и
Vial/Keychron Vial/QMK. Все copyleft, все в режиме `docs`, ни строки кода не
перенесено. Что именно взято, что сознательно не взято и во что это превратилось
в коде — [ui-prior-art.md](ui-prior-art.md).

Одна заметка о лицензиях оттуда стоит того, чтобы быть и здесь: у OpenRGB в этой
таблице режим `facts` (для RGB-опкодов), а в UI-разборе — `docs`. Это не
противоречие: режим ограничивает то, что можно взять, и `docs` строго уже, чем
`facts`.

## Планируемая инкорпорация кода (влияет на дизайн заранее)

Требование тикета: явно назвать, какой permissive-код реально планируется взять, потому что это влияет на форму `MouseProtocol`/`ProtocolEngine` **до** фазы 6.

1. **libratbag (MIT) → `mouse.*`-слой, фаза 6.** Планируется портирование протокольной логики отдельных драйверов (не всей библиотеки: у libratbag своя DBus/meson/C-инфраструктура, которая нам не нужна). Следствия для дизайна уже сейчас:
   - libratbag работает в модели «устройство → профили → резолюции/кнопки/LED», где **профиль — сущность на устройстве**, а не в приложении. Наш `dev.profiles` (`spec.md` Приложение A) уже это отражает; при дизайне `pprofile` нужно сохранить приоритет hardware-профиля над software-профилем (`spec.md` FR6) — это ровно та модель, что у libratbag, и портирование будет дешёвым только если мы её не сломаем.
   - libratbag абстрагирует «kernel/hardware quirks» отдельным слоем — соответствует нашему `quirk(device_id, key, value, reason)` в реестре (Приложение B). Совпадение не случайное, менять схему quirk'ов без нужды не стоит.
   - MIT требует сохранения копирайт-нотиса → нужен экран/файл third-party notices в приложении. **Follow-up:** отдельного тикета на third-party-notices пока нет; фиксируется здесь как известный пробел, создать при первой фактической инкорпорации permissive-кода (фаза 6 / TICKET-19), не раньше.
2. **ratbag-emu (MIT) → `tools/emu`, TICKET-14.** Планируется взять дизайн и, при совпадении, куски кода эмуляции HID-устройства. Следствие для дизайна: эмулятор должен уметь **имитировать конкретную модель с её firmware-багами**, а не быть абстрактным HID-эхом — иначе он не проверит наш анти-фикция-фильтр (`spec.md` FR5). Это уточняет acceptance criteria TICKET-14, но не меняет их.
3. **he-analog-gamepad (MIT) → аналоговый стрим, фазы 2–4.** Планируется портировать процедуру включения аналогового режима и разбор аналогового репорта (Python → Rust) как первый реальный `he.analog_stream` для Sonix `0x3151`-семейства. Следствие для дизайна: `CapValue` обязан поддерживать stream-форму с первого дня (уже зафиксировано в `architecture/INITIAL_REVIEW.md` §5) — это подтверждающее свидетельство, а не новое требование. Второе следствие: активация стрима — это **запись** (HID Feature Report), т.е. первая же демо-фича проходит через `psafety`/`SafeCommandId`, а не в обход; учесть при декомпозиции TICKET-15.

## he-analog-gamepad: отдельно (требование acceptance criteria TICKET-03)

Проект даёт готовый вход в аналоговый стрим конкретно для **Attack Shark X68 PRO HE**, контроллер **Sonix**, **VID `0x3151` / PID `0x5030`** — это подтверждено на странице репозитория (2026-08-17). Релевантность для ROYUAN-трека:

- VID `0x3151` — тот же, что у основной массы ROYUAN-плат по данным sharkfin. Значит аналоговый стрим, вероятно, доступен на всём этом семействе, а не только на X68 PRO HE. **Это гипотеза, не факт** — проверяется эмпирически в TICKET-09.
- Стрим читается с **отдельного vendor-specific интерфейса** (в проекте — интерфейс 2, `mi_02`), а не из клавиатурной коллекции. Это прямое (положительное) свидетельство по открытому вопросу **Q2** в `spec.md`: на как минимум одной реальной плате аналоговый стрим сидит в отдельном TLC и **доступен на Windows** из user-space (проект работает на Windows, использует ViGEmBus). Q2 не закрывается — одна плата не статистика, — но перестаёт быть чистой неизвестностью.
- Технические факты стрима (report ID, разметка байтов, диапазон значений, команды включения/выключения) вынесены в [royuan.md](royuan.md), чтобы весь протокольный слой лежал в одном документе.

## Изменения к плану, вытекающие из инвентаризации

Ни одно не меняет acceptance criteria существующих тикетов; всё — уточнения, зафиксированные для последующих фаз:

1. **`spec.md` Q2 (аналоговый стрим в vendor-TLC) получил первое положительное свидетельство** — см. выше. Формулировку в `spec.md` не меняю: вопрос по-прежнему решается эмпирически в TICKET-08/09, а свидетельство из чужого проекта ≠ проверка на нашем железе (`origin: FromVendorJs`-класса доверие, не `Verified(hw)`).
2. **Третий permissive-источник кода вместо двух.** План исходил из «libratbag для мышей»; фактически permissive также ratbag-emu (эмулятор) и he-analog-gamepad (аналог). Последнее особенно меняет расклад: самая рискованная и самая «флагманская» фича v1 имеет prior art, который можно легально портировать, а не только конспектировать.
3. **Нужен third-party notices артефакт** (следствие MIT-атрибуции) — зафиксировано выше как follow-up без отдельного тикета до фактической инкорпорации.
4. **Официальный репозиторий SignalRGB-плагинов не показывает лицензию** — до выяснения он относится к режиму `facts` по правилу default-deny, и является кандидатом на источник для изолированного `tools/ingest` (TICKET-18), а не для основного дерева.

## Что осталось непроверенным

Честный список, чтобы следующий тикет не принял это за проверенные факты:

- транспорт `hmkconf` (WebHID vs нативный) — на странице репозитория не задокументирован;
- наличие/назначение отдельного `vial-gui` — по странице `vial-qmk` не подтверждено;
- текущий формат определения плат в QMK (`info.json` vs `keyboard.json`) — уточнять по docs.qmk.fm;
- лицензия официального `signalrgb/signal-plugins` — на странице проекта не отображается, LICENSE-файл не проверен;
- «GPL» у OpenRazer уточнён GitHub'ом без версии в выдаче — по данным проекта это GPL-2.0, но версия не подтверждена первоисточником в этом проходе. Для режима `facts` версия не критична; при любой попытке взять код — перепроверить.
